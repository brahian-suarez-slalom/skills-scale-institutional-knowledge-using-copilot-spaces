# OctoAcme Project Management Docs

This folder brings together OctoAcme’s project management guidance. OctoAcme uses a customer-first, iterative lifecycle: initiate work by validating the need, defining measurable outcomes, aligning stakeholders, and deciding whether to proceed; plan approved work as a prioritized backlog with acceptance criteria, estimates, milestones, dependencies, and a Definition of Done; then execute in small increments, release and verify the work, and capture lessons in a retrospective.

Ownership is shared across clear roles. The Project Manager coordinates delivery, schedules, risks, dependencies, and communication; the Product Manager defines outcomes, priorities, and success measures; developers design, build, and test; QA validates quality and acceptance; and stakeholders provide input and approvals. Teams use project boards, standups, delivery and stakeholder syncs, demos, and a shared status source to keep progress visible and surface blockers. Risks are recorded, assessed, mitigated, monitored, and escalated through the appropriate path.

Quality is built into delivery through acceptance criteria, a Definition of Done, automated tests and linting, security scans, code review, and appropriate integration, end-to-end, or manual QA. Releases are prepared with release notes, smoke tests, and rollback or mitigation plans, then verified and communicated. Retrospectives after sprints, releases, milestones, or incidents turn learnings into a small set of owned, measurable improvement actions.
